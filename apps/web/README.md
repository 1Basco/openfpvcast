# Open FPV Cast — web frontend

The SvelteKit UI of Open FPV Cast. It runs inside the Capacitor WebView on Android and talks
to the hardware layer through the `capacitor-dji-aoa` plugin (USB/AOA, DUML, H.264 decode —
see `plugins/capacitor-dji-aoa/`). The root [`README.md`](../../README.md) covers the product
and the overall build; this file covers only the frontend.

## Stack

- **SvelteKit 2 / Svelte 5** (runes), static adapter — the build output in `build/` is what
  `cap sync` copies into the Android project.
- **Tailwind CSS 4** + [shadcn-svelte](https://shadcn-svelte.com) components (`src/lib/components/ui/`).
- **Paraglide-JS** for i18n — messages in `messages/{en,pt-BR}.json`, compiled to
  `src/lib/paraglide/` (git-ignored, regenerated by `pnpm run paraglide` / `prepare` / `check`).

## Layout

| Path | What |
|---|---|
| `src/routes/` | `/` (two app modes), `/camera`, `/settings` (app settings), `/recordings`, `/debug` (developer mode only) |
| `src/lib/components/` | UI components — `HomeScreen` / `StreamingMode` are the two top-level app modes; `common/` holds the design primitives (section labels, segmented control, value strips, rows) |
| `src/lib/stores/` | App state: connection, stream, camera, recording, autorecord, broadcast, settings, telemetry, orientation, debug |
| `src/lib/aoa/` | Typed wrappers over the plugin API (camera commands, DUML helpers) |
| `src/lib/schemas/` | Camera capability tables per model (O4 Lite / O4 Pro) |
| `messages/` | i18n source messages (`en` is the source locale) |

Two architectural notes worth knowing before editing:

- **The app's two modes are state-driven, not routes.** `/` renders `HomeScreen` or
  `StreamingMode` from the connection/stream stores — navigating away would unmount
  `VideoPreview` and tear down the native video window. That is also why the in-stream camera
  panel expands the video format inline instead of linking to `/camera`.
- **The video is a native SurfaceView, not an HTML element.** `VideoPreview.svelte` only
  reports its bounding rect to the plugin, which punches the video through the WebView at
  that position. Anything that must appear above the video must live inside the WebView
  normally (the WebView itself stays on top).

## Commands

```sh
pnpm dev          # dev server (browser only — native plugin calls are no-ops)
pnpm build        # production build into build/
pnpm check        # paraglide compile + svelte-kit sync + svelte-check
```

On-device testing always goes through the root project: `pnpm sync && pnpm exec cap run android`.
